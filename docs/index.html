PRACTICAL GUIDE

From curve
to motion.

A curve describes how a value changes. A Tween or animation supplies the time. Connect them to make a popup settle, a door glide, or a charge build.

Time 0 → 1→curve.sample(t)→ Property

Use built-in Tween transitions when a standard ease is enough. Use Easing Curve when you want to edit the shape visually, tune its parameters, add segments, or reuse one authored resource across effects.

Your first Tween

  1. Install the packaged plugin under res://addons/easing_curve/. Enable Easing Curve in Project Settings → Plugins.
  2. Attach the script below to a Node2D with something visible beneath it. Select the node, create a New EasingCurve in the exported Curve field, and choose a preset.
  3. Run the scene. Edit and save the resource to reuse the same motion elsewhere.
extends Node2D
@export var curve: EasingCurve

func _ready() -> void:
	var tween := create_tween().set_trans(Tween.TRANS_LINEAR)
	var motion := tween.tween_property(self, "position:x", 300.0, 1.0)
	if curve != null:
		motion.set_custom_interpolator(curve.sample)

Time and distance stay separate. The Tween above takes one second and ends at x = 300 for a curve ending at 1. Change the duration to change speed; change the resource to change the feel. Its input stays linear so you don’t apply easing twice.

New in the development version (1.2.3-dev): the examples below are in res://addons/easing_curve/examples/ and will be included in the next packaged release. They are not in the stable v1.2.2 ZIP. Use a source checkout containing the examples, or copy the complete examples directory into an installed addon. Open a scene and press F6. These examples use portable GDScript resources and need no Native library.

Start small, grow past the target, then settle. Back · Out gives a confirmation panel a little weight. This same connection works for position, rotation, color, and other Tween-compatible properties.

In Godot

Open popup.tscn. The root owns a centered PanelContainer named Popup. Press Replay, then adjust the root’s Curve → Back Overshoot and replay the effect.

	panel.pivot_offset = panel.size / 2.0
	tween = create_tween()
	tween.set_trans(Tween.TRANS_LINEAR)
	var motion := tween.tween_property(panel, "scale", Vector2.ONE, maxf(duration, 0.05))
	if curve != null:
		motion.set_custom_interpolator(curve.sample)

The complete script kills the old Tween and resets scale before replaying. Keep overshoot for motion; clamping would flatten the effect. Scale changes are visual and do not change a Container’s layout allocation.

Use Smoothstep · In Out to ease a sliding door at both ends. AnimationPlayer animates one exported progress value; the script converts that into a position.

In Godot

  1. Open sliding_door.tscn. Select its AnimationPlayer and the open animation.
  2. Inspect the root’s progress value track: a key at 0 seconds has value 0, and a key at 1 second has value 1. Track interpolation is Linear and key transition is 1.
  3. Run the scene. Replay opens the door; Close plays the same animation backwards. The exported Duration scales the one-second clip.
@export_range(0.0, 1.0, 0.001) var progress := 0.0:
	set(value):
		progress = clampf(value, 0.0, 1.0)
		if is_node_ready():
			var weight := curve.sample(progress) if curve != null else progress
			door.position = closed_position.lerp(open_position, weight)

This is a bridge through a scripted property, not a new AnimationPlayer track type. Keep other tracks for sounds or synchronized visuals. The door script runs at runtime; scrubbing the editor timeline alone does not preview its derived position. This example moves a visual panel, not a physics body.

A charge shaped by your curve

A curve does not need to animate a node. Here the saved CSS cubic Bézier curve maps elapsed progress into charge. Its controls are cubic-bezier(0.25, 0.1, 0.25, 1); the preview below uses samples exported from that resource.

In Godot

Open charge_meter.tscn. Replay supplies linear progress through tween_method(). Drag the slider to stop playback and sample a particular moment. Change the curve's CSS cubic Bézier controls, press Replay, and compare the result.

func apply_charge(value: float) -> void:
	progress = clampf(value, 0.0, 1.0)
	var weight := curve.sample(progress) if curve != null else progress
	meter.value = clampf(weight, 0.0, 1.0) * 100.0
	scrubber.set_value_no_signal(progress)
	%Readout.text = "Time: %.2f   Sample: %.3f   Charge: %.1f%%" % [progress, weight, meter.value]

For your own timer, use clampf(elapsed / duration, 0.0, 1.0) with a positive duration. Feed the sampled value into opacity, shader strength, camera zoom, or another value. Clamp only when that value has bounds. The complete meter script keeps the slider and readout synchronized.

ITERATE IN CONTEXT

Edit a value, then press Replay

  1. Open an example scene, select its root in the Local scene tree, and expand the exported Curve.
  2. Save the scene and resource, then run the current scene with F6.
  3. After changing Curve or Duration, press Replay in the running scene to compare the effect from its starting position. Press Replay after undoing an edit, too.
  4. If the running scene still has the old values, save your edits and run it again with F6, then press Replay. Use the charge meter's slider to inspect a particular progress value.

These example scripts are runtime scripts, not @tool scripts. Editing a value in the editor does not run their animation there. Replay starts a new effect using the values available to the running instance; it does not reload arbitrary files from disk.

Local and Remote are different. Local edits author the resource you will save. Remote edits affect the running instance and are not a way to save your design. Save and rerun when local edits have not reached the running instance.

The scripts also listen to Resource.changed, so a change that reaches the running resource may restart motion automatically or refresh a parked meter. Use Replay after each edit for a consistent comparison. Editing a shared resource can affect multiple nodes; use Make Unique before giving one effect its own curve.

Want to compare easing against Godot’s built-in transitions? The existing comparison scene remains at res://addons/easing_curve/_test_scene/test.tscn.

Compatibility

Plugin v1.2.2 supports Godot 4.4.1 and newer. This project’s primary validation runtime is 4.7.1. EasingCurve remains supported and portable. Native is supported on Windows x86_64 and non-threaded Web; use the packaged release ZIP because GitHub source archives omit its binaries.

To adapt a recipe for Native, change the exported type, create/assign a NativeEasingCurve, and keep curve.sample. The full example scripts also type their setter fields as EasingCurve, so update that declaration when adapting them. Do not cast between the two families or copy numeric transition IDs; use Inspector conversion to create a separate copy.

Common pitfalls

  • “It doesn’t accept this resource.” EasingCurve extends Resource, not Godot’s Curve. Use its sample method in your script; it is not a drop-in replacement for Curve-only properties.
  • “The timing looks different.” Use a Linear Tween transition and linear AnimationPlayer progress. Additional easing changes the input before sampling.
  • “The effect fights itself.” Kill the previous Tween before starting another on the same property.
  • “It doesn’t reach the target.” A curve ending at 0.8 produces 80% interpolation. Use endpoints (0, 0) and (1, 1) when you want an ordinary start-to-finish transition. Constant, Jitter, and custom curves may intentionally behave otherwise.
  • “My edited shape vanished.” Changing a geometry-generating preset parameter can replace manually edited points. Undo restores the previous geometry.
