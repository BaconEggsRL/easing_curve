# Easing Curve v1.0.9 Release Notes

Easing Curve v1.0.9 focuses on faster curve evaluation and drawing, improved editor navigation and resource browsing, tighter Godot-theme integration, and stronger release/test infrastructure.

## Highlights

### Resource-browser curve previews

EasingCurve resources now generate thumbnail previews in Godot's resource browser. The thumbnail is sampled from the same `EasingCurve.sample(x)` behavior used at runtime, making saved curve resources easier to identify visually.

### Point navigation in the graph toolbar

The selected-point toolbar now includes previous/next navigation arrows and a centered `P#` indicator. The shipping v1.0.9 behavior is selection-only:

- previous/next changes the selected point without changing point order;
- navigation wraps between the first and last point;
- point geometry and Undo history are unchanged by navigation alone;
- Function mode keeps point navigation unavailable.

The experimental reorder behavior remains internal and is not part of the advertised v1.0.9 interaction.

### Faster Bézier rendering and sampling

Editor graph rendering now uses visible-range clipping and adaptive Bézier tessellation to avoid unnecessary drawing work.

Runtime Bézier sampling now compiles segment data behind a dirty-invalidated cache. Strictly ordered curves use locality checks and binary lookup, while duplicate-X, reversed, and overlapping layouts retain the previous linear first-match behavior through a compatibility fallback.

Measured against the retained linear reference over 150,000 samples on Godot 4.7.1:

| Points | Compiled | Linear reference | Speedup |
| ---: | ---: | ---: | ---: |
| 2 | 2.31 us/sample | 3.21 us/sample | 1.39x |
| 16 | 2.94 us/sample | 5.96 us/sample | 2.02x |
| 128 | 8.42 us/sample | 28.22 us/sample | 3.35x |

A randomized 128-point access pattern measured 2.98x faster than the retained linear reference.

### Improved Bounce parameter editing

Bounce curves now support:

- `num_bounces` from 1 through 20 instead of 1 through 10;
- slider-preferred integer editing for `num_bounces`;
- `bounce_damping` adjustment in 0.01 increments instead of 0.1.

### Editor integration and view behavior

- External EasingCurve resources receive one initial Autofit when first opened in the Inspector.
- Later Inspector rebuilds continue to preserve the resource's current in-session graph view.
- Editor UI icons are sourced through a cached Godot editor-theme helper instead of redundant bundled icon copies, improving theme consistency and reducing plugin asset weight.

## Reliability and maintenance

The v1.0.9 development pass also reorganized editor/runtime/test internals and centralized point-state transition logic used by live point edits and Inspector snapshot mutation. Existing public EasingCurve APIs, point identity/order semantics, serialized point keys, Handle Modes, Force Linear behavior, notifications, and Undo/Redo contracts were intentionally preserved.

The update checker was corrected so `update_available` is emitted independently of debug logging.

## Test infrastructure

Registered automated suites now live under `test/scripts/`, with the authoritative PowerShell runners under `test/runners/`. The manifest contains 18 suites: 8 headless and 10 Editor-host.

The runner now classifies top-level Godot diagnostics from stdout, stderr, and `godot.log`. `SCRIPT ERROR:` is always fatal, and any unclassified top-level `ERROR:` or `WARNING:` fails the suite and preserves its artifacts. Known intentional serialization diagnostics and measured headless Editor shutdown diagnostics remain visible and narrowly allowlisted.

Final v1.0.9 code-closeout validation on Godot 4.7.1:

- 18/18 registered suites passed;
- runner exit 0;
- 18 PASS markers;
- 93 expected diagnostics explicitly classified;
- 0 unexpected diagnostics;
- 0 `SCRIPT ERROR:`.

## Not included in v1.0.9

The following previously discussed work is intentionally left for a future release or separately approved maintenance pass:

- persisting graph zoom/pan through editor or project restarts;
- graph playback/playhead/sample-animation controls (resource-browser thumbnails are separate and do ship in v1.0.9);
- multi-point selection/editing;
- additional saved-resource lifecycle, public-input validation, update-version semantics, and larger architecture/API maintenance work.

## Release-engineering note

This document describes the committed v1.0.9 code scope. At documentation closeout, `plugin.cfg` still reports `1.0.9-dev`; the final version bump, visible-editor release smoke, claimed-version compatibility checks, and package/export inspection remain release-engineering gates rather than additional production-feature work.
