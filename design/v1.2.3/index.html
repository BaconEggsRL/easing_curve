A compact list and one editing surface. Fewer fields on screen, but more selection changes.

Further ownership alternatives · annotated candidates

Curve per phase: Enter, exit, and press can each supply defaults. This fits interactions but introduces phase ownership into generic animation.

Normalized timeline: offsets and duration multipliers support coordinated gestures; they also drift toward timeline authoring. The strip above is deliberately read-only.

Shared duration + multiplier: convenient proportional timing but harder to predict than explicit seconds. This lab exercises shared, per-track, and shared-with-override seconds.

LAB 02 / BINDINGS

The destination
can change.

Animate Character.position toward Character.target_position. Preview both, then change the destination during the delay to compare Play-time and track-start capture.

FIXED MOCK SCENE · TYPED PROPERTIES

Four modes, visible intent

Current reads the target at the capture boundary. Value uses a literal. Relative adds an offset to that captured value. Property reads another compatible property once. It does not follow a moving source continuously.

A picker, not a path guessing game

The mock registry includes components, custom script values, and material parameters. Production could use Object.get_property_list() and Shader.get_shader_uniform_list(). Bool is excluded: choose a discrete action if that is needed later.

Godot’s from_current() captures when the PropertyTweener is created. A proposed “read at track start” mode needs deliberate runtime resolution. These names are not interchangeable.

LAB 03 / INTERACTION

Feel the difference.
Then choose the wiring.

Hover, press, or tab into a button. Architecture switches change the authoring and signal route while keeping the animation implementation and recipe the same.

RECOMMENDED FOR EVALUATION · COMPANION VS HELPER

One overlap rule, openly provisional

Press takes transform priority. Otherwise hover or focus adds emphasis. Focus keeps its own visible accent. Release returns to the still-active hover/focus state; a newer event cancels motion from the current visible value.

What the original button taught us

The local JuicyButton project already auditions Inspector events, squashes on press, lifts on hover, and uses separate return curves. Its captured starting position motivates the layout-change experiments. Focus behavior is new exploration.

Signal names are mapped to browser events for UX evaluation. No Godot input dispatch, signal connection storage, or scene-tree lifecycle is simulated.

LAB 04 / RETURN BEHAVIOR

Back to…
which normal?

Compare returning to captured values with returning to a fresh external baseline. Move the layout or change its base scale after playback, then choose Return.

SNAPSHOT ≠ ENDPOINTS ≠ BASELINE
Snapshot editor values→Capture playback endpoints→Preview / stop / reverse→Reset snapshot

Exact reverse

Traverse the captured curve backward from the current progress. This is distinct from swapping endpoints and applying a new easing curve.

Fresh baseline

Return to an external source of intended layout state. Reading a currently animated value cannot reveal what another system meant “normal” to be.

Engine requirements

Real preview would need capture/restore across editor selection changes, scene closure, target deletion, plugin shutdown, and undo operations. Those remain design constraints, not browser implementations.

Convenience API candidates

Every example below is proposed syntax unless explicitly marked existing. No EasingTween API exists in this lab.

CANDIDATE · CONFIGURED NODE
$HoverTween.play()
$HoverTween.reverse()
$HoverTween.play_to(destination)

Discoverable on a scene node. Multitrack play_to needs an explicit target-track policy before production.

CANDIDATE · CURVE CONVENIENCE
curve.tween_property(button, ^"scale", Vector2(1.08, 1.08), 0.12)
curve.tween_property(node, ^"position:y", target_y, duration)

Easy to discover from the resource. Both independent curve families would need a consistent contract.

Returning a Tween preserves cancellation and completion control; a PropertyTweener exposes property modifiers. A wrapper return type adds a concept. Compare these before adding API. An optional curve.interpolate(initial, delta, elapsed, duration) would also need explicit zero-duration and extrapolation semantics.

Repository constraints

  • Legacy and Native are supported independent resource families; numeric transition IDs are not interchangeable.
  • Current project: Godot 4.7, validated sample export: 4.7.1. Existing release compatibility: 4.4.1+. Native requires a matching binary.
  • Sampling clamps time, not output. Curves may overshoot or have unusual endpoints; no automatic normalization is implied.
  • Curve Reverse/Invert transforms are separate from playback reversal. The browser never mutates a shared sample table.
  • Existing editor backends unify Inspector presentation, not runtime animation ownership.
  • Godot 4.7 offset transforms require enabling. With visual-only enabled, hit testing stays at the original location. The wrapper alternative is separately shown for older supported versions.

NEXT / DECIDE WITH EVIDENCE

A small animation tool.
A clear boundary.

Finish the lab review before choosing production scope. These recommendations are hypotheses to test, not a v1.2.3 feature commitment.

Use EasingTween when…

A compact property gesture needs Inspector authoring, dynamic destinations, or simple replay. Use code Tween when procedural composition is already clearer in code.

Use AnimationPlayer / Tree when…

Choose AnimationPlayer for long authored sequences, coordinated keys, and scrubbing. Choose AnimationTree for blending and animation transitions.

FUTURE · NOT IMPLEMENTED

Bake a curve into authored keys?

Fixed endpoints + curve→Sample + measure error→Property keys / Bézier tracks→AnimationPlayer

Bounce, Elastic, Spring, Jitter, and arbitrary functions may need sampled keys. A single cubic Bézier cannot generally reproduce them. Sampling needs error bounds and care around discontinuities and overshoot; dynamic Property destinations must be frozen before baking.
